## 生产落地要点

- **按风险给工具分级**：只读（查询）→ 可逆的写操作（改地址）→ 不可逆或涉及资金的操作（退款、删除、对外发邮件）。只有最后一类需要人工审批，否则审批人会被“同意”按钮淹没，最后闭着眼点同意。
- 审批的粒度可以很细：比如“退款金额 ≤ ¥200 自动通过，超过的需要主管审批”。这类规则写在代码里，不要指望模型自己判断。
- **状态必须可序列化**。审批可能要等几个小时，期间服务可能重启、扩容。把 state 存进数据库（按 run id），恢复时在任何一台机器上都能接着跑。LangGraph 的 `interrupt()` + checkpointer、OpenAI Agents SDK 的 `needsApproval`，都是同一个思路。
- 审批界面要给人看**模型到底要做什么**：工具名、完整参数、模型给出的理由，以及相关的上下文（这个订单金额多少、客户是谁）。审批人不该需要去翻日志。
- 拒绝不是异常，而是一种**结果**：把拒绝原因作为 `is_error` 的 tool_result 交给模型，它会自己调整方案或者如实告诉用户。
- 恢复时要防止**重复执行**：同一个审批被点了两次、或者恢复过程中崩溃重试，都可能导致退款执行两次。给有副作用的工具加幂等键（第 6 关），并在执行前检查这个 tool_use_id 是否已经处理过。
- 审批记录本身就是审计日志：谁、在什么时候、批准了哪个调用、参数是什么，都要留存，满足合规要求。
