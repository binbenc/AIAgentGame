## 生产落地要点

- **首字延迟（TTFT）是体感速度的关键指标**。总耗时 6 秒、首字 0.5 秒的回答，比总耗时 3 秒但要干等 3 秒的回答“感觉更快”。监控里要分别统计 TTFT 和总耗时。
- 从服务端推到浏览器，常用 **SSE**（Server-Sent Events）：单向、基于 HTTP、能自动重连，各家模型 API 本身也用它。需要双向通信时才考虑 WebSocket。注意中间的反向代理（如 Nginx）要关掉响应缓冲，否则流式会变成“攒一大块再发”。
- **取消要传到最底层**：前端断开连接 → 服务端 abort 对模型的请求。只在前端停止显示，模型还在后台继续生成，token 照样计费。Anthropic 和 OpenAI 的 SDK 都支持传入 `signal`。
- 被取消的回答要妥善处理：已经生成的部分是否写入对话历史？通常做法是保留，并标记为“已中断”，让下一轮的模型知道上一条回答没说完。
- **首字超时比总超时更早发现问题**：模型服务过载时，常见的表现是迟迟不出第一个字。首字超时之后，可以重试、切换到备用模型或者降级回复。
- 流式的工具调用参数是**一段段的 JSON 片段**（`tool_input_delta`），要等整个块结束后才能解析，别对半截 JSON 调用 `JSON.parse`。SDK 一般都提供了 `finalMessage()` / `finalResponse()` 这样的辅助方法。
- 长任务除了流式输出文字，还要推送**结构化的进度事件**（“正在查询物流…”“第 2/4 步”），前端据此显示状态，而不是只显示一个转圈。
