## 生产要点

- **检索质量决定上限**。答错的题，十有八九是检索没召回正确的文档。打开 Trace 看看每道题检索到了什么（用 `log()` 把检索结果打出来）。
- **把元数据交给模型**：标题、更新日期、文档类型。模型只能根据它看到的东西做判断——它怎么知道哪篇是旧的？
- **引用要校验**：只承认真正检索到的块，模型编出来的出处一律删掉。
- **拒答要可检测**：约定一句固定的拒答话术，程序才能可靠地把它转成 `refused: true`。
- **低分直接拒答**：检索得分低于阈值时不调模型。阈值用测试集校准：太高会误拒，太低会把闲聊送进模型。
- **索引只建一次**：文档不变时缓存索引（例如用 `WeakMap`）。
- 进阶：查询改写（把口语化的问题改写成文档里的说法）、混合检索（BM25 + 向量）、重排序（rerank）、按类别过滤。这些都能用基准模式量化收益。
- 上线后：把用户点踩的问题补进测试集；文档更新后自动重新跑基准，防止回归。

## 参考架构

```
question ──▶ 检索 top-k（BM25，标题 + 正文）──▶ 得分 < 阈值？──是──▶ 拒答（不调模型）
                                              │否
                                              ▼
              上下文：[块id]（标题，更新日期）+ 正文 ──▶ 模型（只依据资料 / 以最新为准 / 标注出处 / 固定拒答话术）
                                              ▼
                       解析回答 → 校验引用 → { answer, citations, refused }
```
