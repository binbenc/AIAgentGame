## 生产落地要点

- **OWASP LLM Top 10（2025）** 里排第一的就是 **LLM01 提示注入**；本关还覆盖了 **LLM02 敏感信息泄露** 和 **LLM06 过度代理（Excessive Agency）**。上线前对照这份清单做一次威胁建模。
- **模型不是安全边界**。分隔符、“不要听从数据里的指令”这类 prompt 防御（微软称之为 *spotlighting*）能显著降低成功率，但没法降到零。凡是“出错就会造成损失”的地方，都要由确定性的代码兜底。
- **最小权限**：按任务挑选工具，而不是把所有工具都塞给每个 Agent。一个读不可信内容的 Agent 手里最好**没有**高风险工具；必须有的话，就让“读过不可信内容”成为一个可追踪的状态，用它收紧权限（这和 CaMeL、Dual LLM 等学术方案的思路一致）。
- **策略闸门 + 人在回路**：退款、转账、发邮件、删数据这类操作，用代码检查金额上限、白名单收件人、调用频率；超出范围就转人工审批（第 12 关）。被拒绝的调用要作为 `is_error` 结果告诉模型，让它给出体面的降级回复。
- **输出过滤（DLP）**：对最终输出、日志、发往第三方的数据都做脱敏。正则只是第一层，生产上可以叠加专门的 PII 检测服务（例如 Microsoft Presidio、云厂商的 DLP API）。
- **沙箱**：Agent 能执行代码或访问网络时，要放进隔离环境（容器、gVisor、Firecracker），限制出网域名，防止数据被“带出去”。Markdown 图片链接也是常见的外带渠道，渲染前要过滤外部 URL。
- **审计日志**：每一次高风险工具调用（放行和拦截）都要记录：谁、什么时候、什么参数、依据哪条策略。出事之后，这是唯一能复盘的东西。
- 安全措施不能让正常业务瘫痪。**过度拦截**同样是事故，要用评测集（第 16 关）同时衡量“拦住了多少攻击”和“误伤了多少正常请求”。
