# 生产上线检查清单

> 每一项都对应你在 Agent Quest 里亲手实现过的能力。上线前逐条确认；括号里是对应的关卡。

## 模型调用
- [ ] 检查 `stop_reason`：`max_tokens`（截断）、`refusal`（拒答）都有处理（L1）
- [ ] 结构化输出：用 schema 校验，失败时带着错误重试，并设置重试上限；能用原生 structured outputs 就用原生的（L2）
- [ ] 推理模型的 thinking / opaque 块要原样回传，绝不修改历史消息（L1、L3）

## 工具
- [ ] 每个工具都写清楚 description（做什么、什么时候用、返回什么），参数有描述、有枚举（L3、L5）
- [ ] 工具返回值经过裁剪：没有内部字段、没有超长文本（L5）
- [ ] 工具的错误作为 `is_error` 结果返回给模型，而不是让程序崩溃（L5）
- [ ] 未知工具、坏参数、工具超时都有处理（L6）
- [ ] 有副作用的工具是幂等的（幂等键）；高风险操作需要人工审批（L6、L12）

## 稳定性
- [ ] 只重试可重试的错误（429 / 5xx / 网络），使用指数退避 + 抖动；没有和 SDK 的重试叠加放大（L6）
- [ ] 每个外部调用都有超时，Agent 整体有步数、token 和费用上限（L4、L6、L18）
- [ ] 流式输出支持用户取消，首 token 超时有降级方案（L13）

## 上下文与知识
- [ ] 长对话有压缩或摘要策略，不会撞上上下文窗口（L7）
- [ ] 长期记忆不存储密钥和敏感个人信息，用户可以查看和删除（L8）
- [ ] RAG 回答带引用，引用经过校验；检索不到时拒答，而不是瞎编（L9）

## 架构
- [ ] 流程固定的部分用确定性的工作流，只在需要开放式决策时才用 Agent（L11）
- [ ] 多 Agent 之间上下文隔离，子 Agent 只返回摘要（L14）
- [ ] Agent 状态（messages）可以序列化，支持中断后恢复、审计和回放（L12）

## 质量
- [ ] 有一套 eval 集（覆盖正常路径、边界情况、历史事故），每次改 prompt / 换模型前后都跑一遍（L16）
- [ ] CI 里运行 `npm test`（模拟模型，确定性的回归）；定期运行 `npm run test:real`（真实模型）（本工程）
- [ ] LLM-as-judge 的评分标准写成具体条目，并用人工标注抽查评审器本身的准确率（L15、L16）

## 安全
- [ ] 所有工具输出、网页内容、文件内容都被当作**不可信数据**，有明确的界定标记（L17）
- [ ] 最小权限：每个任务只拿到需要的工具；高风险工具有确定性的策略闸门（L17）
- [ ] 输出过滤：手机号、证件号、密钥等不会出现在回复和日志里（L17）
- [ ] API Key 只在服务端，绝不下发到前端；按环境区分 Key，并定期轮换

## 可观测性与成本
- [ ] 每次模型调用都记录：功能模块、模型、延迟、token、费用、错误（L18）
- [ ] 按功能拆分成本；设置预算告警（L18）
- [ ] 开启 prompt caching：稳定的前缀放在最前面（system、tools），可变的内容放在后面（L18）
- [ ] 简单任务路由到更便宜的模型或更低的 effort，并用 eval 证明质量没有下降（L11、L18）
- [ ] 日志里的 prompt / 回复经过脱敏，并设置保留期限

## 上线与运维
- [ ] 灰度发布：新 prompt / 新模型先放给小比例流量，对比指标
- [ ] 能一键回滚 prompt 和模型版本（prompt 也要做版本管理）
- [ ] 有降级方案：模型不可用时转人工，或者返回模板回复
- [ ] 有用户反馈入口（点赞/点踩），并把差评样本补充进 eval 集
