## 生产落地要点

- **上下文窗口是硬上限，成本是软上限**。多轮对话每一轮都要重发全部历史，总 token 随轮数近似**平方**增长。给每个会话设 token 预算，并且留出输出 token 的余量。
- 先数再发：Anthropic 提供 `messages.countTokens` 接口，OpenAI 可以用 `tiktoken` 在本地估算。**工具定义、system、图片都算在内**，别只数 messages。
- 常见压缩策略：① 滑动窗口（直接丢掉最早的轮次，最便宜但会失忆）；② **摘要 + 最近 N 轮**（本关做法，最常用）；③ 清理旧的工具结果（大段 JSON 往往最占地方，Anthropic 的 context editing 就是自动做这件事）；④ 把关键事实抽取到外部记忆（下一关）。
- **只在轮的边界切**：`tool_use` 和 `tool_result` 必须成对出现，第一条消息必须是 user。切坏了会直接收到 400。
- 摘要可以用便宜的小模型（`model: 'fast'`）来做；摘要 prompt 要点名必须保留的信息（订单号、金额、用户承诺过的事、未解决的问题），并要求“不要编造”。
- 摘要本身也会变长：多次压缩时要把旧摘要一起再压，并给摘要设 `max_tokens`。
- 压缩会**让 prompt 缓存失效**（前缀变了）。所以不要每轮都压，而是等接近阈值时一次压到明显低于阈值，这样缓存命中率和成本都更好。
