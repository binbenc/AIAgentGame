## Production notes

- **Why MCP**: without a standard, connecting M AI apps to N tool systems takes M×N integrations; MCP makes it M+N. Besides the **tools** covered here, the protocol defines **resources** (readable context data) and **prompts** (reusable prompt templates), plus client-side capabilities offered to servers such as sampling and elicitation.
- **Don't hand-roll the protocol**: in production use the official SDKs — `@modelcontextprotocol/sdk` for TypeScript (`McpServer` / `Client`) and `mcp` for Python (including FastMCP). Writing it once by hand is about understanding what the messages look like; you'll thank yourself when debugging.
- **Transports**: local processes use **stdio** (the client spawns a subprocess and exchanges messages over stdin/stdout); remote services use **Streamable HTTP** (a single HTTP endpoint that can upgrade to an SSE stream when needed, replacing the older HTTP+SSE transport). The protocol layer is decoupled from the transport, which is why this level's in-memory transport works too.
- **Auth**: remote MCP servers use **OAuth 2.1** (authorization code + PKCE), with the server acting as a resource server that validates tokens. Don't put long-lived API keys in client configs, and don't pass user tokens through to downstream services.
- **Trust boundaries**: third-party servers are untrusted. **Tool descriptions themselves are an injection surface** ("tool poisoning": instructions hidden in a description), and a server can quietly change its tool definitions after you've approved them (a "rug pull"). Allowlist servers, pin versions, review changes to tool descriptions, and treat returned content as untrusted data (Level 17).
- **Name collisions**: several servers may all have tools like `search` or `get_status`. A server prefix is the usual fix (Claude Code uses `mcp__server__tool`); with many tools, pick tools dynamically per task or use tool search.
- **Two layers of errors**: protocol errors (unknown method, unknown tool, malformed params) go in the JSON-RPC `error`; tool execution failures go in `result.isError: true` so the model can see them and adjust. Mix them up and either the model never sees the error or the whole call chain falls over.
- **The Anthropic API's MCP connector** lets the Messages API connect to remote MCP servers directly, so you don't need your own client — but you're still responsible for whether the server can be trusted.
