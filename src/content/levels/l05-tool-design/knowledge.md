## 生产落地要点

- **工具是 Agent 的 API，使用者是模型**。设计原则和给人用的 API 一样：名字清楚、参数少而明确、用枚举约束取值、错误信息能指导下一步怎么做。
- 工具的**粒度**要按“任务”划分，不要照搬后端接口。比如 `search_orders(email, status)` 比 `find_customer` + `list_orders` + 让模型自己过滤要好：步数更少、更可靠、更省 token。
- 返回值要**投影/裁剪**：内部字段、超长文本、二进制数据都别直接丢进上下文。长列表要分页，并告诉模型怎么翻页。
- 错误要**作为结果返回**（`is_error: true`），内容写成可操作的指引，例如“订单已发货，无法取消；可以在签收后申请退货”。
- 有副作用的工具（取消、退款、发邮件）要考虑**幂等**（重复调用不会重复执行）和**审批**（第 12 关）。
- 工具数量变多（几十个以上）后，考虑按场景动态挑选工具，或者使用 tool search，而不是一股脑全塞进去。
