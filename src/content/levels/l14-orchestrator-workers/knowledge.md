## 生产落地要点

- 多 Agent 最大的收益是**上下文隔离**，而不是“角色扮演”。每个子 Agent 在干净的上下文里处理大量原始数据，只把压缩后的结论交回去——编排者的上下文始终又小又干净。Anthropic 的多 Agent 研究系统、Claude Code 的 subagent 都是这个思路。
- **子任务要写清楚**：目标、范围、输出格式、可用工具、什么时候停。描述含糊时，多个 worker 会重复劳动或互相留空白。
- **最小权限的工具集**：worker 只拿它需要的工具，既减少选错工具的机会，也缩小出事时的影响面。
- 并行带来的是**延迟**收益，不是成本收益：总 token 往往比单 Agent 更多（多 Agent 系统常见 3~15 倍）。只在任务能被拆成互相独立、价值够高的子任务时用；强依赖顺序的任务用工作流（第 11 关）。
- **部分失败要显式化**：worker 自己兜底异常，结果里标记 `partial`，最终答案告诉用户缺了什么——比整份报告失败、或者悄悄编一段好得多。
- 给编排者的子任务数量、每个 worker 的步数和 token 都设上限，避免“拆出 50 个子任务”这种失控。
- 可观测性：给每个 worker 打上子任务 id，trace 里能按 worker 看耗时和 token。
