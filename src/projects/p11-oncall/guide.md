## 生产要点

- **先确认，再排查**：告警是“症状”，不是诊断。先看告警指标最近 30~60 分钟的曲线和错误日志——只有一两个点越线、之后已经恢复，就是抖动；4xx 突增往往是客户端或压测。误报的正确处置是“什么都不做”，然后建议调整告警的阈值或持续时间。
- **沿依赖拓扑走**：gateway 报 502，往往是下游第二、三层出了问题。给模型拓扑工具，让它逐跳看下游的错误率和错误日志，找到“自己出错、而不是被别人拖累”的那个服务；也别忘了反方向——上游的重试风暴会压垮下游。外部依赖没有指标，只能从调用方的日志里看出来。
- **相关不等于因果**：两个服务一起变差时，看**时间线**：谁的异常先开始、谁的变更早于异常。晚于异常开始的发布不是原因，哪怕那个服务的指标更难看。把“变更必须早于异常”写进 system prompt。
- **工具输出要为模型设计**：60 个点的时间序列、几十行重复日志直接塞给模型，又贵又难读。把指标压缩成“基线 / 最大值 / 当前值 / 异常开始时间 + 稀疏采样”，把日志按内容去重并标上次数和首末时间。但**不要截断掉关键信息**——截掉的那一行可能就是 `x509: certificate has expired`。
- **审批是代码里的闸门，不是提示词里的愿望**：在处置工具里先 `requestApproval`、批准了才执行，驳回就把驳回意见作为错误返回给模型。理由的模板写进工具参数说明：根因服务 + 指标数值 / 日志原文 + 为什么这个操作能解决问题。人类审批人看的就是这些证据（第 12 关的人工审批 + 第 17 关的策略闸门）。
- **最小处置**：只动根因。“把受影响的服务都重启一遍”会掩盖证据、扩大影响；数据库故障切换会造成写中断，只有主库实例真的不可达时才做。高风险动作在审批端设更高的证据门槛。
- **手册是 Agent 的长期记忆**：很多处置有顺序（先关日志开关、再重启；先确认是哪一方的证书）。让模型先查手册再动手，比指望它“自己悟”可靠得多。
- **第三方故障：升级，不要乱动**。重启、回滚自己的服务解决不了供应商的问题。Agent 的产出是一份状态通报：影响范围、开始时间、正在联系谁、下次更新时间。
- **输出要能落地**：根因用固定枚举（方便统计和告警路由），总结按复盘模板写（影响 / 根因 / 证据 / 处置），证据引用原文。真实的 AIOps 基准（ITBench、AIOpsLab）同样按“根因定位 + 处置后系统是否恢复”打分。
- 上线后：每次真实事故都转成一个新的注入场景（告警 + 指标 + 日志 + 变更），持续跑基准；处置动作全部进审计日志。

```
alert ──▶ system（排查流程 + 时间线规则 + 最小处置 + 审批理由模板 + 输出 JSON / 复盘格式）
           │
           ▼
  ┌────────────────────────── runAgent 循环（maxSteps ≈ 25）──────────────────────────┐
  │  模型 ──▶ 读：get_topology / get_metrics（压缩摘要）/ search_logs（去重计数）         │
  │           get_deploy_history / get_runbook / list_services                         │
  │       ──▶ 写：rollback / restart / scale / toggle_flag / failover（都带 reason）     │
  │                    │                                                               │
  │                    ▼  处置工具内部：requestApproval({action,args,reason})            │
  │               批准 ──▶ 执行原始 API ──▶ 结果     驳回 ──▶ 把驳回意见作为错误返回     │
  └──────────────────────────────────────────────────────────────────────────────────┘
           │ 模型不再调用工具
           ▼
  parseJsonLoose ──▶ { rootCause: { service, category }, summary: 影响 / 根因 / 证据 / 处置 }
           │
           ▼
  判定器：审批记录 ✓ 根因 ✓ 没碰无关对象 ✓ 系统恢复 ✓ 复盘证据 ✓
```
