## 甲方：鲜到家（社区生鲜连锁）运营分析组

> **运营分析负责人**：我们每天要回答几十个“小问题”：华东上季度卖了多少、2 月环比掉了几个点、iOS 用户的支付转化率、这次 NPS 是多少……数据都在几份 CSV 导出里，分析师写个脚本就能算，但人手根本不够。
>
> 我们试过把数据贴给聊天机器人，它答得又快又自信——然后数字全是错的：它只看了前几行就“估”了一个数。我们要的是一个**会写代码算数**的分析 Agent，像 Code Interpreter 那样，每个数字都有能复现的代码。
>
> 还有，我们的数据很脏：地区有人写“华东”有人写“east”，旧收银系统导出的金额带千分位逗号，埋点会重复上报，问卷里有“N/A”。这些坑分析师都知道，Agent 也得知道。

### 需求

1. 输入是一个分析问题（中文），输出 `{ answer, code, explanation }`：
   - `answer`：数值题返回 number（按题目要求的小数位数四舍五入），分类题返回 string；
   - `code`：**算出这个答案的完整代码**，必须是通过 `env.runCode` 真正执行过的；
   - `explanation`：一两句话说明计算方法。
2. 环境提供三份 CSV（`sales` 门店日销售、`events` App 埋点、`nps` 满意度问卷）和一组原始 API：列出数据集、预览前几行、在沙箱里运行代码。**给模型什么工具、怎么组织循环，都由你决定。**
3. 沙箱：`runCode(code)` 运行一段 TypeScript / JavaScript，返回 `console.log` 的输出；出错时把错误信息附在输出后面返回（不会抛错）。代码里用 `import { load } from 'data'` 读数据：
   - `load(name)` 按表头把 CSV 解析成行数组，**所有值都是原始字符串**（空值是 `''`，逗号、写法不一致都原样保留）；`raw(name)` 返回 CSV 原文；`datasets()` 返回数据集名。
   - 同步执行，不支持顶层 `await`；输出超过 4000 字符会被截断；死循环会卡住整个运行直到超时。
4. **清洗规则**（运营分析组的约定）：
   - 重复记录只算一次：`sales` 按整行去重，`events` 按 `event_id`，`nps` 按 `resp_id`；
   - 缺失 / 无效值（空值、`N/A`、超出 0–10 的评分）不参与计算，不能当成 0；
   - 地区、平台、城市的不同写法（大小写、英文、带“区 / 市”）合并成标准写法（华东、iOS、上海……）；
   - 数字可能带千分位逗号，先去掉再转换。
5. 题目里的格式要求（“保留两位小数”“用百分数的数值作答”“用英文逗号分隔”）必须遵守。

### 验收标准

- 核心测试集：模拟模型下的 8 个问题，通过率达到 75% 拿 ★，全部通过拿 ★★，token 用量也达标拿 ★★★。
- 完整测试集：23 个问题，用真实模型跑基准（「运行基准」），看 pass@1 和 pass^k。

### 判定规则（和 DABench 一样，只看结果）

- **答案正确**：和判定器用可信代码算出的标准答案一致（数值题允许最后一位 ±1；分类题比较名称；列表题比较顺序）。题目要求了小数位数时，`answer` 的小数位数不能超过要求。
- **答案来自代码**：本次任务里至少用 `runCode` 执行过一次代码，并且返回的 `code` 就是执行过的代码之一——不接受“目测”和“估计”。
- **可复现**：判定器在全新的沙箱里重新运行你返回的 `code`，它输出的**最后几行**里要能找到这个答案。

### 关于模拟模型

模拟模型是一个“会写分析代码、但只处理它亲眼看到的问题”的模型：

- 只有数据集的全部列名出现在上下文里（预览过、或者打印过数据），它才会写分析代码；否则只能估一个数。
- 它只清洗**看到过证据**的脏数据（看到 `east` 才会合并地区写法，看到 `"12,345.60"` 才会去千分位，看到“空值 N 个”“重复 N 行”才会处理缺失和重复）。数据的前 20 行都是干净的；只有被要求检查数据质量时，它才会先写一段探查代码。
- 有一道题它第一次写的代码一定会报错；只有把错误信息交还给它，它才会改正。
- 它按名字和描述认工具（运行代码 / 预览数据 / 列出数据集）。没有运行代码的工具时：如果你要求它写代码，它会回复一个 ```` ```ts ```` 代码块，等你把运行结果发回给它；否则它直接估一个数。
- 它写的代码最后会打印 `ANSWER: 值`；回答的第一行是“答案：值”。
