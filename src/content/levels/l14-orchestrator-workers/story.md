周一早会，**Mia（产品经理）** 甩过来一个需求：

> **Mia**：下周要过年度规划，我需要一份竞品调研简报——智能门锁、扫地机器人、智能音箱三条产品线，价格、核心参数、用户口碑都要对比。能不能让 Agent 帮我跑一下？

你把搜索、规格库、电商评价三个工具一股脑塞给了一个 Agent。结果它跑了 3 分钟：九份原始网页、规格表和评价列表全堆在同一个上下文里，后半程开始把门锁的价格安到音箱头上，账单上的 token 数也让人倒吸一口凉气。

> **老周**：一个 Agent 的上下文就是它的“工作记忆”，你往里倒了几万字的噪音，它当然会糊涂。换个思路：让一个**编排者**先把任务拆开，每个子任务交给一个**全新的 worker**——它只拿自己需要的工具，在自己干净的上下文里查完，**只交回一段摘要**。几个 worker 同时干，编排者最后只看摘要写结论。

> **老周**：还有，三个 worker 里挂了一个，不能整份报告都不要了。告诉 Mia 哪部分缺数据，其它照常交付。
